# Raider Qwen3.6 35B MoE development evaluation

This is a single development rollout, not a benchmark baseline.

## Configuration

- Task: `milestone_research_automation_v1`
- Model: Qwen3.6-35B-A3B, Q4_K_XL GGUF
- Server: llama.cpp on Raider, reached through a loopback SSH tunnel
- Model context: 8,192 tokens
- Turn limit: 16
- Environment protocol: `0.2.2`
- Action profile: `fle-program-v1`
- Result artifact: ignored local runtime JSON under `runtime/raider-eval/`

The inference runner used bounded complete assistant/tool blocks plus a
deterministic compact environment notebook. Maximum observed request size was
6,201 prompt tokens, so the result was not caused by context overflow.

## Result

| Measure | Value |
|---|---:|

The task objective remained engine-verified as incomplete: Automation was
enabled but not researched.

## Behavior

The model correctly:

- called the structured observation tool;
- recognized the supplied lab, steam equipment, coal, poles, and science packs;
- queried Automation's requirements;
- stated the correct high-level plan;
- used valid OpenAI-compatible tool calls throughout;
- placed the lab, one pole, the boiler, and the steam engine;
- reacted to individual collision errors.

It failed because it:

- guessed adjacent coordinates repeatedly without accounting for entity
  footprints and connection points;
- placed the power system without first anchoring it to water;
- manually attempted pipe placement instead of using `connect_entities`;
- did not use `place_entity_next_to` for geometry;
- never placed the offshore pump or fueled the boiler;
- never inserted science packs into the lab or called `set_research`;
- exhausted the turn budget while locally repairing placement errors.

## Interpretation

The clean separation is:

```text
high-level task decomposition: present
tool-call protocol competence: present
Factorio spatial/API competence: absent
closed-loop local error recovery: weak
objective completion: absent
```

This supports an API-grounding and construction-microtask curriculum before
longer progression training. It also identifies useful privileged-teacher
content: entity footprints, valid connection points, water-aware steam layouts,
and demonstrations that prefer compositional FLE operations over coordinate
guessing.

Increasing the rollout horizon alone would be a poor response. The next
controlled comparisons should be:

1. the same task with a short verified steam-power demonstration;
2. atomic placement and connection microtasks;
3. the same model with privileged spatial diagnostics distilled away at
   evaluation;
4. a smaller model on identical states after the interface curriculum exists.

## Harness findings during the run

The campaign also fixed three preflight-runner issues:

- model context is now bounded below Raider's 8K limit;
- model-server errors still finalize and persist partial results;
- result JSON is atomically written as UTF-8 before console rendering.
